#### ⑥-1 현장 게첩 작업지시서 (실제 양식)

협회가 실제로 현장 작업반에 넘기는 **「현수막 게시 작업지시서」**(작업지시서_261123.pdf) 양식을 그대로 구현했습니다.

- **헤더** — 제목 `□ 현수막 게시 작업지시서`, 우측에 게시 주간의 월·화·수 설치일(`11월 30일 / 12월 1일 / 12월 2일  작업지시서`). 월요일은 게시 시작일 이후 첫 월요일을 자동 계산합니다.
- **요약 두 줄** — `· 철거(회수) : 총 N매 ( 월 A매, 화 B매, 수 C매 )` / `· 설치(게시) : 총 M매 ( 월 D매, 화 E매, 수 F매 )` + `고장·제외 N개소(M매)`.
- **표 구조** — 첫 열 `게시대 · 단`, 그 뒤 **녹색 `회수 할 현수막`**(광고내용·업체)과 **주황 `게시 할 현수막`**(광고내용·업체) 병렬.
  - 슬롯 라벨은 게시대의 게시대수량(대수)과 열수로 자동 생성합니다 — `의료원사거리A1~A4`(4대×5열) → A1~A5, B1~B5 … / 대수가 1개면 `석림주공사거리1~5`.
  - 고객이 **세부 위치(A2)** 를 지정한 건은 그 줄(`의료원사거리A2`)에 그대로 놓입니다. 밑으로 밀리지 않습니다. 같은 자리에 회수·게시가 같이 있으면 동시에 짝을 이루어 보입니다.
  - **회수** = 지난 회차까지 게시된 현수막(상태 `게시중`·`입고완료`), **게시** = 이번 회차 배정분(`입고대기`·`입고완료`·`게시중`·`선착순확정`).
  - 빈 칸은 공란으로 두어 작업반이 어느 단을 떼고 어느 단에 걸지 한눈에 보게 했습니다.
- **자동 제외** — 고장(수리중) 게시대, 미입고취소·미입금취소·본인취소·낙첨·반려 건은 표에 나오지 않습니다.
- **필터·인쇄** — `전체 / 월요일 / 화요일 / 수요일` 칩(개소 수 표시), `빈 게시대 포함(전체)` 토글(77개소 575슬롯 전체), `작업지시서 인쇄` 버튼.

- 하단에 `작업일 / 작업반 / 확인(사무국)` 서명란.

## 3. 추첨 알고리즘 설계

### 3.1 설계 원칙

1. **순서 무관** — 접수 시각, 금액, 담당자와 배정 결과가 통계적으로 무관해야 한다.
2. **재현 가능** — 같은 입력·같은 시드로 언제든 같은 결과를 다시 계산할 수 있어야 민원에 답할 수 있다.
3. **사전 규칙 고정** — 친환경 우선 비율, 1개소 1매 원칙, 게시대별 정원은 추첨 **전에** 확정해 공개한다.
4. **기록 우선** — 시드, 참여 명단 해시, 결과 해시, 실행자, 시각을 남긴다.
5. **순위 순차 배정** — 1순위 → 2순위 → 3순위로만 넘어가고, 앞 순위에서 배정된 매수는 뒤 순위에서 다시 배정하지 않는다. **고객장소 지정 접수는 1순위에서만** 참여한다.
6. **고장 게시대 제외** — 관리자가 고장(수리중)으로 표시한 게시대는 가용 면 0으로 두어 추첨·접수·선착순에서 모두 빠진다.
7. **세부 위치(동·단) 고정** — 고객이 `A2`처럼 지정한 건은 **그 자리에만** 배정하고, 그 자리가 차면 다른 자리로 밀지 않고 낙첨으로 둔다(형평·현장 혼선 방지).

### 3.2 절차

```
[1] 대상 확정   시안 승인 + 반려·중복 제외  → pool
[2] 시드 생성   seedStr = 회차 | 추첨시각(ISO) | 참여 접수번호(정렬) | 난수 salt
                seed    = FNV-1a(seedStr) → 32bit
                PRNG    = mulberry32(seed)          ※ 재현 가능한 결정적 난수열
[3] 가용 면     게시대(P01~P77) capLeft = 고장(수리중)이면 0, 아니면 (정원 − 공문 우선배정 면)
                → 슬롯으로 관리: slotLeft[p] = [A1, A2, …] 중 공문이 앞 단부터 선점한 자리를 뺀 목록
[4] 1순위 배정  게시대마다 그 게시대를 1순위에 넣은 접수를 모아
                 (a) 세부 위치를 지정한 건을 먼저 — 지정한 자리(A2)가 비어 있으면 그 자리에만 배정.
                     이미 공문·다른 당첨 건이 잡은 자리면 그 건은 낙첨(다른 자리로 밀지 않음)
                 (b) 위치 무관 건은 (a) 뒤 빈 칸에 친환경(정원의 30% 한도) → 나머지 순서로 배정
[5] 2순위 배정  잔여 면이 남은 게시대마다 그 게시대를 2순위에 넣은 접수 중
                 · designatedOnly = false
                 · 배정 매수 < 신청 수량  · 이미 그 게시대에 배정되지 않은 건만 무작위 배정
                 · 같은 광고주가 인접 게시대 택1(14개 구역)의 반대편에 이미 배정됐으면 제외 → adjSkip 증가
[6] 3순위 배정  [5]와 같은 규칙(3순위). 이후로도 배정 매수는 신청 수량을 넘지 않음
[7] 확정       배정 0매 → 낙첨 / 일부만 배정 → 부분 배정 (예: 10개소 신청 → 8개소 배정)
[8] 기록       seed, pool_hash, result_hash, awarded/loser 수, 순위별 배정 수, 택1 제한으로 차단한 건수 → draws(로그 포함) + audit_logs
[9] 당첨 후    상태 '입고대기' + 배정 게시대(assignedPlaces, stage 포함) + 배정 매수 + 입고 마감(수 18:00) 부여
```

### 3.3 핵심 코드 (프로토타입 발췌)

```js
function drawEngine(pool, seedStr) {
  const seed = hash32(seedStr);            // FNV-1a 32bit
  const rnd  = mulberry32(seed);           // 결정적 PRNG
  const shuffle = arr => { /* Fisher–Yates */ };
  pool = pool.slice().sort(byId);          // 입력 순서에 영향받지 않도록 정렬
  /* 가용 슬롯 — 고장이면 0, 공문 우선배정은 앞 단부터 선점 */
  placements.forEach(p => {
    const codes = p.broken ? [] : slotCodesOf(p);        // ['A1','A2',…'D5']
    slotsLeft[p.id] = codes.slice(officialSeatsOf(p.id));
  });

  [1, 2, 3].forEach(stage => {             // 1순위 → 2순위 → 3순위
    placements.sort(byId).forEach(p => {
      if (p.broken || !slotsLeft[p.id].length) return;
      const list = pool.filter(a =>
        (stage === 1 || !a.designatedOnly) &&      // 고객장소 지정은 1순위만
        prioOf(a, stage).includes(p.id) &&         // 해당 순위에 넣은 게시대인가
        got(a) < qtyOf(a) &&                       // 아직 신청 수량을 못 채웠는가
        !hasPlace(a, p.id));
      const desig = a => slotFor(a, p.id);         // 이 게시대에 지정한 자리(A2 등)
      /* ① 지정 자리 — 그 칸이 비어 있을 때만, 경합이면 1건만 */
      shuffle(list.filter(a => desig(a))).forEach(a => {
        if (!slotsLeft[p.id].includes(desig(a))) { stat.slotMiss++; return; }   // 찼으면 낙첨
        give(a, p.id, a.eco, stage, desig(a));
      });
      /* ② 위치 무관 — 남은 빈 칸에 (친환경 우선 → 나머지) */
      shuffle(list.filter(a => !desig(a) && a.eco)).forEach(a => give(a, p.id, true,  stage, slotsLeft[p.id][0]));
      shuffle(list.filter(a => !desig(a) && !hasPlace(a, p.id) && got(a) < qtyOf(a)))
        .forEach(a => give(a, p.id, false, stage, slotsLeft[p.id][0]));
    });
  });
  return { seed, out, stat };   // out[id].places = [{pid, qty:1, stage, slot:'A2'}, …]
}
```

### 3.4 복잡도와 성능

- 신청 `n`건, 게시대 `m`개소(78), 접수당 선택 게시대 `k`(≤50), 순위 3단계 → **O(3·m·n + n·k)**. 주간 회차 수백 건에서도 1초 이내입니다.
- 정렬은 접수번호·게시대번호 기준 1회, 셔플은 게시대마다 2회(친환경/일반)로 결과가 입력 배열 순서에 좌우되지 않습니다.

### 3.5 검증(감사) 방법

| 항목 | 프로토타입 | 실제 운영 권장 |
|---|---|---|
| 난수 | FNV-1a + mulberry32(32bit) | `crypto.getRandomValues`로 salt 생성 + **SHA-256** 시드, PRNG는 공개 구현 |
| 시드 공개 | 추첨 직후 화면·감사 로그에 표시 | 추첨 전 시드를 봉인 공개하거나, 추첨 후 시드·명단·결과 해시를 홈페이지 게시 |
| 재현 | "같은 시드로 재계산·검증" 버튼 | 검증 스크립트를 공개해 제3자가 직접 실행 |
| 참관 | — | 추첨일시(매주 월 10:00) 공지 후 광고주·시 관계자 참관, 화면 녹화 보관 |

> 프로토타입의 32bit 해시는 **시연·재현 확인용**입니다. 실서비스에서는 SHA-256 이상과 서버측 비밀 salt, 시각 동기화(NTP), 실행자 2인 승인 절차를 권장합니다.

             │
             ├─[수 18:00 미입고]─▶ 미입고취소(반려, 사유: 현수막 실물 미제출) + 페널티

### 3.7 미입고 처리 규칙 (구현 상세)

| 단계 | 규칙 |
|---|---|
| 대상 | `입고대기` 이면서 `delivered = false` 이고 **입고 마감(수 18:00)이 지난** 건만 (마감 전 건은 일괄 취소 대상에서 제외) |
| 처리 | 상태 `미입고취소`, 반려 사유 `현수막 실물 미제출 (수요일 18:00 입고 마감 초과)`, 감사 로그 기록 |
| 1순위 전환 | 같은 게시대를 1·2·3순위로 희망했던 **낙첨자** 중 우선순위 → 접수번호 순으로 1명 승계. 승계자 입고 마감은 **다음 영업일(목) 12:00**으로 안내 |
| 2순위 전환 | 승계 후보가 없으면 해당 면을 **회수 면**으로 집계 → 목요일 선착순 접수에 자동 공개 |
| 마감 | 목요일 24:00 이후 남은 회수 면은 금요일부터 접수 불가, 다음 주 회차 물량으로 이월 |

### 3.8 페널티(접수 제한) 규칙

| 구분 | 규칙 | 프로토타입 구현 |
|---|---|---|
| **제재 대상** | 당첨 후 **본인 사유 취소** · **미입금(입금 지연)** · **수요일 18:00 미입고 자동 취소(반려)** | 관리자 `미입금 취소` / `취소(본인 사유)` / `수요일 미입고 일괄 취소` 실행 시 자동 기록 |
| **제외 대상** | **협회 시안 반려**, 협회 귀책, 천재지변·질병·행정명령 등 | 시안 반려는 상태만 `반려`로 바꾸고 페널티를 생성하지 않음 |
| **제재 단위** | **실제 광고주(사업자등록번호 + 연락처)** | 사업자번호 10자리 또는 광고주명+연락처로 동일인 판정 |
| **제재 강도** | **차기 1개 주 회차 접수 제한** | 발생 회차+1의 회차 ID를 `blockRounds`에 기록 (예: 11월 3주차 위반 → 11월 4주차 제한) |
| **차단 범위** | 주간 추첨 접수 + **목요일 잔여석 선착순** | 주간 접수 1단계 검증, 선착순 예약 확정 시 모두 `activePenaltyFor()`로 차단하고 **사유·제한 회차·해제 주차** 안내 |
| **해제** | 기간 경과 시 자동, 사무국·운영위 인정 시 조기 해제 | `blockRounds`에 현재 회차가 없으면 자동 통과, 관리자 `해제(사무국 인정)` 버튼은 `released` 처리 + 감사 로그 |
| **중복 방지** | 같은 광고주·같은 제한 회차는 1건으로 유지 | 기존 페널티를 찾으면 사유·발생 건만 갱신(중복 생성 없음) |
| **시연 데이터** | 예시 2건 | 한빛건설(주)(본인 사유 취소) · 지곡농협(미입고) — 관리자 표에 `예시` 배지 |

> 2회 재발 시 4주·3회 이상 운영위 심의, 수요일 12:00 이전 자진 취소 시 1회 경감은 기획안의 **제안**이며 이번 프로토타입에는 **1주 제한만** 구현했습니다(README 9장 한계 참고).

| seq | int | 순위 내 선택 순서(표시용) |
| qty | int | 항상 **1** — `check (qty = 1)` |

접수 검증: `count(*) filter (where priority = 1) = applications.qty` (1순위는 수량과 일치), `count(*) filter (where priority in (2,3)) between 0 and applications.qty`.
`applications.designated_only boolean` 이 true이면 `priority in (2,3)` 행이 존재할 수 없고, 추첨에서 priority 1 행만 후보가 됩니다.
**placements.status**에 `maintenance`(고장·수리중)를 추가해 추첨·접수·선착순에서 제외합니다.
→ 배정은 `assignments`에 `(application_id, placement_id, qty=1)` 행으로 기록합니다.

**designs / draws / draw_entries / assignments / payments / members / audit_logs / notices** — 이전 버전과 동일하며, `assignments.status`에 `waiting_delivery | delivered | missed`가 추가됩니다.

### 4.2 관계 요약

```
rounds 1─n applications 1─n application_placements n─1 placements (1개소 1매)
                      1─1 deliveries
                      1─n designs
rounds 1─n penalties n─1 advertiser(정규화 키)
rounds 1─1 draws 1─n draw_entries n─1 applications / placements
draw_entries 1─1 assignments 1─n payments
rounds 1─n reclaimed_slots n─1 placements
```

### 4.3 정합성 규칙(서버)

1. 배정 시 `count(assignments where placement = p and period overlap) < p.capacity`를 트랜잭션 내 검사.
2. 추첨 확정 + `rounds.status='drawn'` + `deliveries` 생성(마감 `deliver_by`)을 **한 트랜잭션**으로 처리.
3. **수요일 18:00 배치**: `deliveries.status='waiting' and due_at <= now()`를 일괄 `missed`로 전환 → `applications.status='미입고취소'` → 차순위 승계(트랜잭션) 또는 `reclaimed_slots` 생성. 배치는 **서버 스케줄러**가 실행하고 관리자 화면은 결과를 조회·재실행만 한다.
4. **목요일 24:00 배치**: 미소진 `reclaimed_slots`를 `expired`로 마감(금요일 접수 차단의 근거 데이터).
5. 모든 상태 변경은 `audit_logs`에 before/after를 남긴다(append-only).

## 7. 프로토타입 사용법 (시연 시나리오, 5분)

1. **`seosan-banner-lottery/index.html`을 브라우저로 엽니다.** (서버·인터넷 불필요)
2. **현황** — 상단 주간 일정 스트립(월 추첨 / 수 입고 / 목 선착순 / 금 마감 / 주말 게첩)을 확인합니다.
3. **접수** — `주간 추첨 접수` 4단계:
   - **① 광고주·내용** — 신청 구분 **일반 업체**(재봉기획, 실제 광고주 자동 입력)·연락처·문구, 필수 동의 2건
   - **② 수량·게시 기간** — **접수 수량 10매**(`+` 버튼 또는 빠른 선택), 11.28 게첩·7일
   - **③ 게시대 선택** — 77개소 중 **1순위 10개소**를 골라야 합니다. 상단 `1순위 0 / 10`에서 시작해, **설치요일(월/화/수) 칩**과 **읍면동·검색**으로 좁힌 뒤 카드 10개를 누릅니다. 3개만 고르고 `다음`을 누르면 `1순위는 수량(10매)과 같은 10개소를 선택해야 합니다.` 안내로 막힙니다. 이어 **2순위 탭**에서 다른 게시대 10개소(선택), **3순위 탭**에서 10개소(선택)를 더 고르면 `1순위 10/10 · 2순위 10/10 · 3순위 10/10`이 됩니다. 1순위에 담은 게시대를 2순위에서 누르면 **중복 차단** 안내가 뜹니다.
     - **세부 위치 지정** — 선택한 게시대 칩의 **`세부 위치`**를 열고 `A동` 칩에서 **`A2`**를 누르면 `A2 지정 (A동 2단)`이 됩니다. 이대로 접수하면 요약·접수증·게시 지정서에 `의료원사거리 A2`, 작업지시서에는 `의료원사거리A2` 줄로 나옵니다. 그 자리에 다른 건이 먼저 잡히면 이 건은 낙첨입니다.
     - **고객장소 지정** 체크박스를 켜면 2·3순위 탭이 `미적용`으로 꺼지고 1순위 10개소만으로 접수됩니다. 이 경우 1순위에서 떨어진 매수는 낙첨입니다. 체크하면 **세부 위치 칸이 자동으로 펼쳐집니다**.
     - **고장 게시대**(예시 `의료원담장`)는 카드가 `고장·수리중 · 선택 불가`로 비활성입니다. 관리자 화면에서 `고장` 버튼을 눌러 복구한 뒤 다시 시도해 보세요.
   - **④ 확인·접수** — 요약에서 **10매·선택 게시대 10개소 목록**, 수수료 **107,000원**(10,700 × 10) 확인 후 **접수 완료** → 접수증에 선택한 10개소가 모두 표시됩니다.
   - 수량을 **51**로 올리면 즉시 `1회 최대 접수 수량은 50매까지입니다.`가 뜨고 다음 단계로 넘어가지 않습니다. **50매**는 77개소에서 50개소를 골라 접수까지 진행됩니다.
   - 실제 광고주에 `석남동 신축상가 분양사업단`(사업자 312-81-20455)을 넣으면 **이미 접수된 광고주**로 차단됩니다(대행사도 동일).
   - 실제 광고주에 `한빛건설(주)`(사업자 123-45-67890)을 넣으면 **페널티(접수 제한)** 로 차단되고, 사유와 **해제 주차(2026년 12월 1주차)** 가 안내됩니다.
4. **관리자** — 토글을 켜고
   - `시안 심사`에서 방금 접수 건 **승인** → 추첨 대상 편입
   - `전산 추첨 시작` → 로그(수량 단위 배정·가상계좌 발급) → **결과표(신청/배정 매수)**·**검증 패널**
   - `현수막 실물 입고 확인`에서 지난 회차 마감 경과 2건 확인 → **수요일 미입고 일괄 취소(반려)** 실행 → 차순위 승계·선착순 공개 + **제재 현황에 페널티 자동 기록**
   - `입고 확인` 체크로 당첨 건 입고 처리 → `게시 시작`, `입금 확인` 옆 **`미입금 취소`**·입고 표의 **`취소(본인 사유)`** 도 페널티를 남깁니다
   - 맨 아래 **제재(페널티) 현황**에서 예시 2건(한빛건설·지곡농협)과 `해제(사무국 인정)` 버튼 확인
5. **선착순** — `미배정 선착순`에서 **시연 기준일: 목요일** 칩을 눌러 접수 가능 상태 확인 → `이 매 예약` → 실제 광고주에 `한빛건설(주)`를 넣으면 **페널티로 차단**, 다른 광고주는 확정(회수 매 1 감소). **금요일** 칩으로 바꾸면 접수 버튼이 막히고 안내 문구가 표시됩니다.
6. **마이페이지** — 내 접수의 상태·타임라인(현수막 입고 단계 포함)·입고 기한 안내가 바뀐 것을 확인합니다.
